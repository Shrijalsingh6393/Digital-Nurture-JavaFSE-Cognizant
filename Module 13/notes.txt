PART 18: Testing Isolation, Mocking & Spies in Jest
----------------------------------------------------

1. Need for Isolation in Testing
--------------------------------
Unit tests must verify code logic in complete isolation from external environments (network APIs, databases, third-party microservices).

Why Isolation Matters:
- Eliminates Flakiness: Prevents test failures caused by external server downtime or network timeouts.
- Speed: Executing unit tests against in-memory mocks is orders of magnitude faster than actual network I/O.
- Deterministic Results: Allows simulating rare HTTP status codes (404, 500, rate limits) reliably.

2. Concept of Mocking & Spies
-----------------------------
Mocking is the practice of replacing real objects or modules with simulated "test double" implementations.
- Mock Function (`jest.fn()`): A dummy function that records calls, arguments, and returns configured values.
- Module Mocking (`jest.mock('axios')`): Replaces an entire npm module with mock functions.
- Spies (`jest.spyOn()`): Observes real function calls while optionally overriding implementation.

3. Mocking `axios` with Jest
----------------------------
To unit test a module calling GitHub REST API (`GitClient.js`) without hitting `api.github.com`:
```javascript
import axios from 'axios';
import GitClient from './GitClient';

jest.mock('axios');

test('should return repository names for techiesyed', async () => {
  const mockRepos = [{ name: 'repo1' }, { name: 'repo2' }];
  axios.get.mockResolvedValue({ data: mockRepos });

  const gitClient = new GitClient();
  const repos = await gitClient.getRepositories('techiesyed');

  expect(repos).toEqual(['repo1', 'repo2']);
  expect(axios.get).toHaveBeenCalledWith('https://api.github.com/users/techiesyed/repos');
});
```
